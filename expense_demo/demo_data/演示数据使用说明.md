# 演示数据使用说明

本目录存放项目早期「智能记账助手（Streamlit 版）」遗留下来的**多模态演示素材**：账单 CSV、小票/支付截图、录音，以及素材生成脚本。

> ⚠️ **先分清两套演示数据，避免混淆**
>
> 当前库中前端（NiceGUI 工作台）的演示数据来自仓库根目录的 `demo_data.py`：它用固定随机种子 `18112026` **在内存中确定性生成**从去年 1 月到今天的账目，**不读取本目录的任何文件**。
>
> 本目录的素材属于另一个用途：它们是供「自然语言记账 + 小票/截图 OCR 录入」这类**多模态流程**做功能演示与接口测试用的静态文件（文字记账、图片 OCR、语音 ASR）。两者定位不同、互不依赖。

---

## 一、当前前端如何运作（读数据的方式）

理解运作原理后，才知道这批素材能用在何处：

1. **数据源**：`app.py` 导入根目录 `demo_data.py`，初始调用 `get_stats(period, anchor)` 得到统计对象；之后每次切换周期/日期都重新调用它。
2. **统计口径**：`get_stats()` 按 `日 / 周 / 月 / 年` 计算起止区间，返回总额、笔数、日均、主要分类、环比、分类占比、趋势序列等；日期不能超过今天，未来周期不可前进。
3. **渲染**：结果交给 ECharts 画柱状图（分类支出）、环形图（支出结构）、折线图（消费趋势）；分类固定为 4 类：交通、餐饮、购物、其他。
4. **后端开关**：`backend.py` 中 `USE_BACKEND_STATS` / `USE_BACKEND_CHAT` 默认都是 `False`，页面只读本地内存数据、**不发任何网络请求**。设为 `True` 并填好地址后，统计改走 `fetch_stats()`（`GET {BASE_URL}{STATS_PATH}?period=month&date=...`），聊天改走 `send_chat()`（`POST {BASE_URL}{CHAT_PATH}`，body `{"message": "..."}`）。
5. **容器**：`Dockerfile` 只把 `app.py`、`demo_data.py`、`backend.py` 复制进镜像，数据每次启动都在内存重新生成，因此容器重启后演示数据会恢复，无需挂载数据卷。

**结论**：想让本目录的素材影响页面显示，必须先把它们接入一个后端接口（见第四节），再打开后端开关；直接把文件放在这里不会改变工作台画面。

## 三、直接用素材做功能测试

素材是为早期那套「文字/图片/语音 → 结构化抽取 → 草稿 → 用户确认入库」的流程准备的，典型验证点：

- **文字记账**：用 CSV 里的商户/金额话术，例如「昨天打车 32 块」→ 应抽出商户、金额、分类、日期。
- **图片 OCR**：上传 `receipt_coffee.png` → 应识别「星巴克咖啡 / 28.00 / 餐饮 / 日期」，并支持确认或修正后入库；同一张图重复上传应被去重。
- **语音 ASR**：上传 `voice_taxi.wav` → 先转写为中文，再抽取「滴滴出行 / 32.50 / 交通」。
- **查账**：「这个月餐饮花了多少」「哪类花得最多」→ 应解析出时间范围与类别，金额由后端计算而非模型自由回答。

> **能力前提**：图片 OCR 需要账号开通多模态视觉模型；语音 ASR 需要平台提供 OpenAI 兼容的 `/audio/transcriptions` 端点。若报「服务未开通 / 404」属正常降级，文字链路不受影响。

## 四、把素材接入当前 NiceGUI 工作台

当前前端不直接读本目录文件。若要让工作台展示 CSV 里的账目，推荐做法是把 CSV 作为**后端数据源**，再按 `backend.py` 约定对接：

1. 写一个后端服务，读取 `seed_transactions.csv`，提供统计接口：
   `GET {BASE_URL}{STATS_PATH}?period=month&date=2026-11-21`
   返回字段参照 `backend.py` 的 `parse_stats_response()`（需含 `range_label`、`total`、`count`、`average`、`categories`、`trend_labels`、`trend`、`previous_trend`）。
2. 如需对话能力，再提供 `POST {BASE_URL}{CHAT_PATH}`，body `{"message": "..."}`，返回 `reply` / `message` / `content` / `text` 之一。
3. 在 `backend.py` 里把 `BASE_URL`、`STATS_PATH`、`CHAT_PATH` 的 `****` 换成真实地址，并把 `USE_BACKEND_STATS`、`USE_BACKEND_CHAT` 设为 `True`。
4. 重启工作台。统计开关打开时分析台会通过后端取数；聊天开关打开时发消息会请求后端并显示回复；两个开关都关闭则完全使用本地内存演示数据、聊天不自动回复。
5. 需要鉴权时在 `backend.py` 的 `HEADERS` 里配置（如 `Authorization`），不要改 `app.py`。

> 注意：CSV 的分类是 8 类，而前端 `demo_data.py` 的图表配色只定义了 4 类（交通/餐饮/购物/其他）。接后端时若使用 8 类，建议在后端把分类归并到这 4 类，或在 `app.py` 的 `CATEGORIES` 与图表配置中补齐颜色，否则未定义的分类可能没有配色。

## 五、重新生成素材

需要重新制作小票图时（均在项目根目录执行）：

```bash
# macOS：重新生成 3 张清晰小票图，覆盖 receipt_*.png
swift expense_demo/demo_data/make_demo_receipts.swift expense_demo/demo_data

# Python：生成早期占位小票图 sample_receipt.png（需 Pillow）
python expense_demo/demo_data/make_demo_receipt.py
```

录音文件为 macOS 中文语音合成（16kHz 单声道 PCM），如需重录可用系统 `say` 生成后转码为 16kHz/mono/16bit WAV。

---

## 六、注意事项

- 所有账目、小票、录音**均为演示数据**，不含真实交易，可随意用于测试与展示。
- 默认工作台是本地演示模式，不启动后端、不调用外部接口；页面上的数据刷新或应用重启后会重新生成。
- 图片/录音若被用于真实 API 测试，请勿把含个人信息的真实小票或录音放进仓库。
- Docker 镜像不包含本目录素材（只 COPY 三个 py 文件）；如要在容器内使用这些素材，需自行挂载或复制进去。
