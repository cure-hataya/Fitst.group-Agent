# AI 智能记账助手 API 接口文档

## 1. 项目基本信息

- 项目名称：个人记账与消费分析 AI 助手
- 后端框架：FastAPI
- Python 版本：3.12
- 后端大语言模型：通义千问 Qwen-Plus
- 后端端口：8001
- 本地接口地址：http://127.0.0.1:8001
- Swagger 文档：http://127.0.0.1:8001/docs
- OpenAPI 文档：http://127.0.0.1:8001/openapi.json
- 当前账单存储：内存存储（重启后数据会清空）
- OCR/ASR 识别：由 NiceGUI 前端侧调用小组 OCR/ASR 模块；本 FastAPI 后端不提供图片或音频识别接口

## 2. 接口返回规范

主要业务接口使用以下字段：

- `success`：操作是否成功
- `message`：操作结果提示
- `data`：业务数据

为兼容原有接口，部分接口仍保留 `record`、`bill`、`answer`、`detail` 等字段。

## 3. HTTP 状态码说明

| 状态码 | 含义 |
|---|---|
| 200 | 请求正常处理 |
| 400 | 消费数据不合法 |
| 404 | 资源不存在 |
| 409 | 发现疑似重复账单 |
| 422 | 请求参数校验失败 |
| 502 | 大模型等云服务调用异常 |
| 500 | 服务器内部错误 |

## 4. 基础账单接口

| 请求方式 | 接口路径 | 功能 |
|---|---|---|
| GET | `/` | 后端首页 |
| POST | `/add` | 添加普通账单 |
| GET | `/records` | 获取账单列表 |
| PUT | `/records/{record_id}` | 修改账单 |
| DELETE | `/records/{record_id}` | 删除账单 |
| POST | `/add/text` | 基础文本记账 |
| POST | `/query` | 基础消费查询 |

### 4.1 普通账单新增

- 请求方式：POST
- 接口路径：`/add`
- Content-Type：`application/json`

请求示例：

```json
{
  "item": "午餐",
  "money": 25
}
```

可通过 `force=true` 查询参数，在确认疑似重复后强制继续保存。

## 5. OCR/ASR 前端识别与账单确认

### 5.1 识别职责

当前约定的调用流程：

1. NiceGUI 前端侧调用队友提供的 OCR 图片识别函数或 ASR 语音识别函数。
2. 前端展示识别结果，允许用户检查和修改项目、金额、类别、日期。
3. 用户确认后，前端将统一格式的账单数据提交给本 FastAPI 后端的 `POST /ocr/confirm`。
4. 后端执行金额校验、日期校验、重复账单检测，并保存确认后的账单。

OCR/ASR 的模型调用、图片上传和音频上传不由本 FastAPI 后端负责。本版本不提供 `POST /ocr/recognize` 或 ASR 识别接口。

注意：如果 OCR/ASR 模块需要 API 密钥，应由运行 NiceGUI 的服务端安全保存，不要把密钥暴露在浏览器端。

### 5.2 账单确认与保存

- 请求方式：POST
- 接口路径：`/ocr/confirm`
- Content-Type：`application/json`

请求示例：

```json
{
  "item": "学校食堂午餐",
  "money": 25.0,
  "category": "餐饮",
  "date": "2026-11-28"
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `item` | string | 消费项目或商家及消费说明 |
| `money` | number | 最终确认的消费金额，必须大于 0 |
| `category` | string | 消费类别 |
| `date` | string | ISO 日期，格式为 `YYYY-MM-DD` |

可选查询参数：

- `force=false`：默认值。发现疑似重复账单时返回 409。
- `force=true`：用户确认仍要保存时，允许继续保存。

此接口既可接收 OCR/ASR 前端识别后经用户确认的数据，也可接收其他需要人工确认的账单数据。

## 6. LLM 智能记账与查账接口

### 6.1 自然语言智能记账

- 请求方式：POST
- 接口路径：`/llm/recognize`
- Content-Type：`application/json`
- 使用模型：通义千问 Qwen-Plus

请求示例：

```json
{
  "text": "昨天打车花了三十二块钱"
}
```

功能说明：

- 自动理解自然语言消费描述。
- 自动提取消费项目、金额和日期。
- 自动识别消费类别。
- 返回识别结果供用户确认。
- 识别成功后不会直接保存账单。
- 用户确认后，再调用相应账单保存/确认接口。

### 6.2 自然语言智能查账

- 请求方式：POST
- 接口路径：`/llm/query`
- Content-Type：`application/json`

请求示例：

```json
{
  "text": "这个月交通消费了多少钱"
}
```

功能说明：

- 自动理解用户的查询意图。
- 自动提取时间范围和消费类别。
- 根据当前账单数据进行统计计算。
- 支持消费总额、消费次数、平均消费、消费金额最高的类别等查询。
- 返回统计结果和自然语言回答。
- 不依赖大模型直接编造消费金额。

### 6.3 异常处理

- 空白输入校验。
- 大模型连接异常处理。
- API 调用超时处理。
- API 密钥认证异常处理。
- API 调用频率限制处理。
- JSON 解析异常处理。

## 7. 消费统计接口

| 请求方式 | 接口路径 | 功能 |
|---|---|---|
| GET | `/statistics` | 消费总体统计 |
| GET | `/statistics/category` | 按消费类别统计 |
| GET | `/statistics/time` | 按时间统计 |

### 7.1 消费总体统计

返回消费总额和账单数量。

### 7.2 按消费类别统计

统计不同消费类别的累计金额。项目约定的八种标准类别为：

- 餐饮
- 交通
- 学习
- 医疗
- 购物
- 娱乐
- 生活
- 其他

### 7.3 按时间统计

返回字段：

| 字段 | 说明 |
|---|---|
| `today` | 当天消费金额 |
| `week` | 本周消费金额 |
| `month` | 本月消费金额 |

所有统计均根据当前后端账单数据计算。当前版本使用内存存储，SQLite 持久化接入尚未完成。

## 8. 当前版本边界与后续整合

- 本后端保留账单确认、校验、重复检测、账单管理、LLM 智能记账、智能查账和统计功能。
- OCR/ASR 识别由 NiceGUI 前端侧调用小组模块，本后端只接收用户确认后的结构化账单。
- 本后端不提供图片识别或语音识别接口。
- 当前账单使用内存存储，服务重启后数据会清空。
- SQLite 数据库接入、前后端联合测试和 Docker 部署仍需后续完成。
